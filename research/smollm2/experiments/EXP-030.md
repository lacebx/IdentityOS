# Experiment EXP-030

**Status:** REVERT
**Date:** 2026-08-24T07:22:03Z

## Hypothesis

A concise, task-agnostic instruction telling the model to verify its own arithmetic and
avoid self-contradiction should improve reasoning and long-task success without hurting
truthfulness.

## Bottleneck

Same as EXP-029: long-task multi-step arithmetic (E01/E02/E03) and tool failures (C01/C02).
This was a refinement/re-attempt of the verify-directive approach.

## Change

`adapters/openai_adapter.py` — `OllamaAdapter._build_messages`: system prompt extended
with a self-verification directive (variant of EXP-029).

Benchmark commit: on `smollm2/idos-beats-bare` at state before EXP-030 apply.

## Expected mechanism

Same as EXP-029: verification instruction → more deliberate token allocation → fewer errors.

## Failure analysis

The verification directive continued to disrupt tool-call formatting. The tools category
dropped from 3/5 to 1/5 — a 2-task regression. **Strongly suspected mechanism:** the
additional system prompt text shifts the model's token budget away from structured
JSON output toward prose self-verification, breaking the tool-call emission loop.

This is the second consecutive REVERT on the verify-directive hypothesis (see EXP-029).

The hypothesis is **falsified** for the current OllamaAdapter approach: a system-prompt
self-verification directive hurts tool-use on SmolLM2-360M more than it helps reasoning.

## KEEP / REVERT

**REVERT** — Both success and category gates failed. Hypothesis falsified (second attempt).
